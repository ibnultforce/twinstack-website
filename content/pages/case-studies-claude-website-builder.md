<p class="imp-text-xl imp-text-slate-600 imp-font-medium imp-mb-8">TwinStack's website builder lets small-business owners with no coding or git knowledge create, design and publish a website from a browser, with Claude doing the planning, writing and design. It is an internal TwinStack product.</p>
<h2>At a glance</h2>
<div class="imp-article-table-wrap"><table class="imp-glance"><tbody><tr><th>Type</th><td>Internal product</td></tr><tr><th>Users</th><td>Small-business owners</td></tr><tr><th>Claude products</th><td>Claude API</td></tr><tr><th>Models</th><td>Claude Opus (first designs), Claude Sonnet (assistant and design review), Claude Haiku 4.5 (summaries)</td></tr><tr><th>Tech stack</th><td>Next.js, Express, MongoDB, Tailwind, GitHub Pages and GitHub Actions</td></tr></tbody></table></div>
<h2>The challenge</h2>
<p>Small businesses need a professional website, but most owners can't write code, use git or design pages. Existing builders still leave them to write the copy and lay out every page themselves.</p>
<h2>The solution</h2>
<p>Every site is its own GitHub repository, copied from one template. The builder app clones it on the server, runs the site's own scripts and commits the result. Publishing pushes to GitHub, where an automated workflow builds, checks and deploys the site to GitHub Pages.</p>
<p>The owner's journey:</p>
<ol>
<li><strong>Create.</strong> The owner names the site and answers a few setup questions. Claude analyses the business, writes those questions and plans the site's pages.</li>
<li><strong>Build.</strong> The server creates each planned page and Claude writes it. The header and footer can use the standard design or a Claude-designed matching pair.</li>
<li><strong>Edit.</strong> A live preview shows the site. Owners can edit text in place, or ask the "Ask Claude" assistant to change pages, menus, details and images.</li>
<li><strong>Publish.</strong> A site check explains in plain words anything that would stop a deploy, with buttons to fix it. Then the site goes live.</li>
</ol>
<h2>How Claude is used</h2>

<p><strong>Changes are always proposals.</strong> Claude never writes straight to the live site. Each change is saved as a proposal, the app builds a preview with the proposal in place, and only then applies and commits it.</p>
<p><strong>Claude keeps context.</strong> Every request includes the site's design rules (responsive, mobile-first, Tailwind), the site profile written at setup, and the latest work log, so Claude stays consistent and remembers earlier changes.</p>
<p><strong>A design review loop.</strong> The first homepage is designed on Claude Opus. The page is then screenshotted in headless Chrome, and a Sonnet model reviews it and returns fixes, which are applied and re-checked.</p>
<p><strong>Cost control.</strong> The server sizes each task as small, standard or complex. Complex work always goes to Claude, while small tasks may first try a cheaper fast model and fall back to Claude if it fails checks. All calls go through a metering proxy that prices each request against the user's credits. New accounts get free credits, and more can be bought through Stripe.</p>
<h2>Results</h2>
<ul>
<li>Owners with no technical skills can go from a business description to a published website.</li>
<li>Every Claude change is previewed and checked before it goes live.</li>
<li>Layered model choice keeps quality high where it matters and cost low on small edits.</li>
<li>Claude is optional: the standard design, text editing and publishing all work without it.</li>
</ul>
