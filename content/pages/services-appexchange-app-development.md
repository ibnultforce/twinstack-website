<h1>AppExchange app development, from idea to listing</h1><p class="imp-lead">We design, build and ship native Salesforce apps for software companies, then take them through Salesforce Security Review and onto AppExchange. We have done the same for four apps of our own.</p>
<div class="imp-ctas"><a class="imp-btn imp-bp" href="https://calendar.app.google/HP3LiuNFisCt6xLo6" target="_blank" rel="noopener">Book a free call</a><a class="imp-btn imp-bg" href="#contact">Send us a message</a></div></div>

<section class="imp-sec" id="what"><div class="imp-w"><h2>What we do</h2><div class="imp-sv-list"><div><h3>Product strategy and architecture</h3><p>We test your idea against Salesforce platform limits, design the data model and agree the packaging and licensing approach before any code is written.</p></div><div><h3>Apex and LWC development</h3><p>Native apps built with Apex, Lightning Web Components and Flow, with the test coverage Salesforce requires for packaging.</p></div><div><h3>Security Review preparation</h3><p>Code scans, CRUD and field-level security checks, sharing and injection fixes, plus the documentation Salesforce asks for, prepared before you submit.</p></div><div><h3>Managed packaging and licensing</h3><p>Managed package setup, namespace, versioning and the License Management App, so you can push upgrades to every customer.</p></div><div><h3>AppExchange listing</h3><p>Listing copy, screenshots, a demo video and the setup steps customers need to install and start using your app.</p></div><div><h3>Releases after launch</h3><p>New features, fixes and testing against each Salesforce release, three times a year.</p></div></div></div></section>
<section class="imp-sec imp-tint" id="process"><div class="imp-w"><h2>How it works</h2><ol class="imp-sv-steps"><li><h3>Discovery and feasibility</h3><p>We map the problem, the target customers and the Salesforce editions you need to support.</p></li><li><h3>Architecture and prototype</h3><p>A data model, a packaging plan and a working prototype you can show to early users.</p></li><li><h3>Build and test</h3><p>Development in short sprints with code reviews, automated tests and a security scan on every release.</p></li><li><h3>Security Review and listing</h3><p>We prepare and submit the package, answer reviewer findings and publish your listing.</p></li></ol></div></section>

<section class="imp-sec imp-tint" id="faq"><div class="imp-w"><h2>Common questions</h2><div class="imp-sv-faq"><details><summary>How long does Salesforce Security Review take?</summary><p>It depends on Salesforce's review queue and how many follow-up rounds your package needs. Plan for several weeks from submission. We scan and fix the package and prepare the documentation before you submit, to keep the number of rounds down.</p></details><details><summary>Do I need a managed package to list on AppExchange?</summary><p>Most AppExchange apps are distributed as managed packages, which protect your code and let you push upgrades to every customer. We set up the package, namespace, versioning and the License Management App.</p></details><details><summary>How much does it cost to build an AppExchange app?</summary><p>It depends on the scope. We work at US$30 (A$47) an hour and give you a fixed quote after discovery. Salesforce may also charge partner or review fees, which are separate from our work.</p></details><details><summary>Can you take over an app another team started?</summary><p>Yes. We start with a code and security review, list what needs fixing before Security Review, and agree a plan with you before making changes.</p></details><details><summary>Will the app work in every Salesforce edition?</summary><p>We design for the editions you want to support and test in each one, so you know before launch which customers can install it.</p></details><details><summary>Can you help after the app is listed?</summary><p>Yes. We handle new features, fixes, customer support questions and testing against each Salesforce release.</p></details></div></div></section>
